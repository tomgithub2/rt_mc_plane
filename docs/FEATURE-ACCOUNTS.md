# 功能规格：账号认证与权限（默认超级管理员）

> 主线（上级 agent）编写的**核心设计**。子代理只做 UI / 契约 / 文案等次要件，改本文须经主线同意。
> 用户要求原文：**「网站要有账号和密码认证，默认账号是超级管理员」**。

## 1. 认证：现状与收口口径

| 能力 | 现状 | 结论 |
|---|---|---|
| 账号 + 密码登录 | 已有：`POST /api/auth/login` → Bearer token | 保留 |
| 口令存储 | 已有：PBKDF2-SHA256、**600,000 次迭代**、每用户独立 salt | 保留（不再降级） |
| 口令策略 | 已有：**≥12 位且至少 3 类字符**（大小写/数字/符号） | 保留，改密同样校验 |
| 失败锁定 | 已有：按 `用户名+IP` 计数，超阈值临时锁定（429） | 保留 |
| 会话 | 已有：`sessions(token, user_id, ip, ua, created_at, expires_at)` + `users.token_epoch` | 保留；**改密 / 踢下线即 bump epoch，全端失效** |
| 审计 | 已有：登录成功/失败、改密、登出 | 保留并扩到用户管理类操作 |
| **角色与权限** | ✗ **`users.role` 只存不用，无任何权限校验** | **本次新增（核心）** |

## 2. 角色模型（从高到低）

| 角色 | key | 能力 | 限制 |
|---|---|---|---|
| **超级管理员** | `super_admin` | 全部：用户与角色管理、面板系统设置（端口/网络/存储/更新）、所有实例的任意操作、查看审计 | **不可被删除/停用/降级**；系统内**至少保留 1 个**；**禁止自我降级或自我停用** |
| 管理员 | `admin` | 管理**所有实例**（启停/命令/文件/插件/备份/任务/建筑导入）、查看审计与日志 | **不可**管理用户与角色、**不可**改系统设置（端口/绑定/存储路径等） |
| 普通用户 | `user` | 只能操作**自己拥有的实例**（`owner_id`），受配额限制 | 不可见他人实例、不可改系统设置、不可看审计 |
| 只读 | `viewer` | 只读查看被授权的实例（控制台/状态/日志） | 一切写操作 403 |

权限点（后端逐个路由 `require_perm` 兜底）：

```
instance.create  instance.delete  instance.start  instance.stop  instance.command
instance.files   instance.plugins instance.backup instance.cron   instance.build_import
instance.settings_network        # 改端口/绑定
user.manage      system.settings audit.view      log.view
```

## 3. 实例归属与配额

- `instances.owner_id` → `users.id`；列表**默认只返回自己拥有的**（`admin`/`super_admin` 可见全部并可筛选）。
- 每用户配额（`users` 增加列或独立 `quotas` 表）：`max_instances`、`max_memory_mb_total`、`max_backups`、`max_upload_mb`、`allow_build_import`。
- 创建实例 / 改内存 / 上传 / 建备份时**逐项校验**，超限返回 **403 + 中文原因**（例如"实例数已达上限 3 个，请联系超级管理员调整配额"）。

## 4. 首次运行：默认账号就是超级管理员

1. 库为空时自动创建**超级管理员**：用户名 `admin`，`role='super_admin'`；
2. 口令**随机生成**（≥16 位，含大小写/数字/符号），**只在本地终端打印一次**；
   **不写入日志文件、不显示在网页、不落盘明文**（库里只有 PBKDF2 哈希）；
3. Linux 安装脚本同样只打印一次（不经网页/邮件下发）；
4. 首次登录后前端**提示**尽快改密（不强制，避免把自己锁在外面），改密动作写入审计；
5. 若用户把唯一的超级管理员口令忘了且没有其它超管：提供**本地重置通道**（服务器上执行一个脚本直接改库，需服务器登录权限）—— 这属于"有服务器权限即可恢复"，不再开别的后门。

## 5. 用户管理 API（本次新增）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/users` | `user.manage` | 列表：用户名、角色、状态、配额、最近登录、实例数 |
| POST | `/api/users` | `user.manage` | 建号 `{username, password, role, quota:{...}}`；口令走同一策略校验 |
| PATCH | `/api/users/{id}` | `user.manage` | 改角色 / 状态（启用停用）/ 配额；**禁止自我降级、禁止停用最后一个超管** |
| POST | `/api/users/{id}/password` | `user.manage` | 重置口令：可留空由服务端随机生成，**响应里一次性回显**（页面只显示一次，可复制） |
| POST | `/api/users/{id}/kick` | `user.manage` | 强制下线（bump `token_epoch`） |
| DELETE | `/api/users/{id}` | `user.manage` | 删除；**禁止自删、禁止删除最后一个超管**；其名下实例需先转移或一并删除（二次确认） |
| GET | `/api/me/permissions` | 登录即可 | 返回 `{role, perms:[...], quota:{...}}`，前端据此隐藏菜单/按钮（**后端仍必须兜底校验**） |

## 6. 前端约束（次要件线执行）

1. **登录页**：账号 + 密码；失败给明确提示；锁定时显示剩余时间；**首次运行引导里写明"默认账号是超级管理员"**；
2. **顶栏**：`用户名 + 角色徽标`（超级管理员 / 管理员 / 普通用户 / 只读），按角色配色区分；
3. **菜单与按钮按权限隐藏**（读 `/api/me/permissions`），越权由后端 403 兜底并 toast 提示"权限不足"；
4. **账号管理页**（仅 `user.manage` 可见）：用户列表（角色徽标、状态、配额、最近登录、实例数）、新建、改角色/配额、重置口令（**一次性回显 + 复制**，关闭后不再显示）、强制下线、删除（二次确认）；
5. **实例卡片**对 `admin`/`super_admin` 显示"归属用户"，对普通用户不显示他人实例。

## 7. 安全红线

- 页面、日志、审计里**永不出现明文口令**；重置口令只在响应里返回一次；
- 所有写接口必须 `require_perm(...)` **后端兜底**（前端隐藏不算安全）；
- 禁止自我降级/自删；禁止删除或停用最后一个超级管理员；
- 会话 token：≥32 字节随机（hex 表示），绑定 IP + UA 哈希；改密/踢人 bump `token_epoch`；
- 用户管理类操作审计为 `warn` 级（含操作者、目标用户、动作、IP）。

## 8. 验收标准（我会亲自跑）

1. 全新库启动 → 终端**只打印一次**超管口令 → 用它登录成功，`/api/me/permissions` 显示 `role=super_admin` 且权限齐全；
2. 建一个 `user` 角色账号 → 它访问他人实例/系统设置/用户管理 → **全部 403**；访问自己实例 → 200；
3. 用 `user` 账号建实例超出配额 → 403 + 中文原因；
4. 重置口令后：旧 token **立即失效**（bump epoch）、新口令可登录、响应只在当次返回；
5. 尝试把唯一超管降级/停用/删除 → 全部被拒；尝试自删 → 被拒；
6. 审计日志里能看到上述每一次操作（谁、对谁、什么动作、IP）。
